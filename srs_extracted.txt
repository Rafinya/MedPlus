1. Introduction 
1.1 Purpose 
This Software Requirements Specification (SRS) document describes the complete 
software requirements for the Pharmacy POS Management System. This system is designed to 
automate and streamline pharmacy operations at MedPlus Pharmacy, a community pharmacy 
located in Nairobi, Kenya. 
The purpose of this document is to provide a detailed specification of the functional and 
non-functional requirements for the Pharmacy POS Management System. It serves as a reference 
for developers, testers, project managers, and stakeholders involved in t he development and 
deployment of the system. 
This SRS covers all aspects of the system including sales transaction processing, medicine 
inventory management with expiry date tracking, prescription record management, receipt 
generation, and comprehensive reporting capabilities. 
1.2 Intended Audience and Reading Suggestions 
This document is intended for the following audiences: 
• Development Team: Software developers who will implement the system. They should 
read the entire document, with particular focus on Section 3 (System Features) and Section 
4 (External Interface Requirements). 
• Project Manager: Responsible for project planning and coordination. Should focus on 
Sections 1, 2, and 6 for scope and constraints understanding. 
• Quality Assurance Team: Testers who will validate the system. Should thoroughly review 
Section 3 (System Features) to develop comprehensive test cases. 
• Pharmacy Management (MedPlus): End users and system owners. Should review Sections 
1, 2, and 3 to ensure requirements align with business needs. 
• Supervisor and Academic Reviewers: For academic evaluation and approval of the project 
scope and requirements.  
 
The recommended reading sequence is: start with Section 1 (Introduction) for overview, 
then Section 2 (Overall Description) for context, followed by Section 3 (System Features) 
for detailed requirements.

1.3 Project Scope 
The Pharmacy POS Management System is a computerized solution designed to replace 
the manual and semi -automated systems currently used at MedPlus Pharmacy. The system will 
provide the following capabilities: 
• Sales transaction processing for both prescription and over-the-counter (OTC) medicines 
• Real-time medicine inventory management with automatic stock level updates 
• Expiry date tracking with automated alerts for medicines approaching expiration 
• Prescription record management and linking to sales transactions 
• Receipt generation and printing 
• Low stock alerts and notifications 
• Comprehensive reporting (sales, inventory, expiry, profit analysis) 
• User management with role -based access control (Admin, Pharmacist, Cashier)  
 
The objectives of the system are to improve accuracy, speed, and reliability in pharmacy 
sales operations; reduce human errors in pricing and inventory tracking; ensure regulatory 
compliance with the Pharmacy and Poisons Board of Kenya requirements; minimi ze 
financial losses from expired stock; and support informed decision -making through 
accurate reporting.  
 
The system will NOT include the following in this initial version: integration with external 
systems such as NHIF (National Hospital Insurance Fund) or supplier databases; controlled 
substance tracking features; multi-branch or chain pharmacy management capabilities; and 
online pharmacy or e-commerce functionality. 
 
2. Overall Description 
2.1 Product Perspective 
The Pharmacy POS Management System is a new, self -contained software product 
designed specifically for MedPlus Pharmacy. It is not a follow-on member of an existing product 
family nor a replacement for a specific existing system, though it will replace the  current manual 
record-keeping practices. 
--- Page 7 ---
   
 
 7  
 
The system operates as a standalone application with a client -server architecture. Users 
interact with the system through web browsers (client layer), the application logic processes 
transactions on the server (application layer), and all persistent data i s stored in a database 
(database layer). 
The major components of the system include: 
• Client Layer: Web browser interface for user interaction 
• Application Layer: Django-based web application handling business logic 
• Database Layer: MySQL/PostgreSQL database for data persistence 
• External Hardware: Barcode scanner, receipt printer, and cash drawer 
2.2 Product Features 
The Pharmacy POS Management System will provide the following major features: 
2.2.1 User Authentication and Authorization 
Secure login system with role -based access control supporting three user roles: 
Administrator (full system access), Pharmacist (inventory and prescription management), and 
Cashier (sales processing and receipt generation). 
2.2.2 Medicine Inventory Management 
Complete inventory tracking including medicine master data, batch management, expiry 
date tracking, stock level monitoring, and automated alerts for low stock and expiring medicines. 
2.2.3 Sales Management 
Point-of-sale functionality including item selection via barcode or search, pricing with 
discount capabilities, multiple payment methods (Cash, M -Pesa, Card), receipt generation, and 
sales history tracking. 
2.2.4 Prescription Management 
Recording and management of prescription details including prescriber information, 
patient details, prescribed medicines, and linking prescriptions to sales transactions for regulatory 
compliance.

2.2.5 Reporting and Analytics 
Comprehensive reporting capabilities including daily/weekly/monthly sales reports, 
inventory status reports, expiring medicines reports, low stock reports, profit margin analysis, and 
export to PDF/Excel formats. 
2.3 User Classes and Characteristics 
The system is designed for the following user classes: 
2.3.1 Administrator 
The Administrator is typically the pharmacy owner or IT specialist responsible for system 
configuration and management. Characteristics include: high technical expertise, full system 
access, responsible for user management, system configuration, and data b ackup. Frequency of 
use: daily for system monitoring and weekly for administrative tasks. 
2.3.2 Pharmacist 
The Pharmacist is a licensed professional responsible for medicine dispensing and 
prescription management. Characteristics include: pharmaceutical knowledge, moderate technical 
skills, manages inventory, processes prescriptions, and verifies medicine infor mation. Frequency 
of use: continuous during working hours. 
2.3.3 Cashier 
The Cashier handles sales transactions and customer interactions. Characteristics include: 
basic technical skills, focuses on sales processing, receipt generation, and customer service. 
Frequency of use: continuous during working hours. 
2.3.4 Patient/Customer (Indirect) 
Patients are the end beneficiaries of the system through improved service quality, accurate 
dispensing, and faster transaction processing. They do not directly interact with the system.

3. System Features 
3.1 User Authentication and Authorization Module 
3.1.1 Description and Priority 
This module manages user access to the system through secure login/logout functionality 
and implements role-based access control. Priority: HIGH. This is a critical security feature that 
must be implemented first. 
3.1.2 Stimulus/Response 
Stimulus: User enters username and password on login page. Response: System validates 
credentials and redirects to appropriate dashboard based on user role. 
Stimulus: User clicks logout button. Response: System terminates session and redirects to 
login page. 
Stimulus: User attempts to access unauthorized functionality. Response: System displays 
access denied message and logs the attempt.

URL 
REQ-AUTH-02: The system shall authenticate users based on username and password

attempts

REQ-AUTH-10: The system shall log all login/logout activities for audit purposes 
3.2 Medicine Inventory Management Module 
3.2.1 Description and Priority 
This module manages all aspects of medicine inventory including master data, stock levels, 
batch tracking, and expiry date management. Priority: HIGH. Core functionality for pharmacy 
operations. 
3.2.2 Stimulus/Response 
Stimulus: Administrator adds new medicine to inventory. Response: System creates 
medicine record and updates inventory database. 
Stimulus: Sale transaction completed. Response: System deducts sold quantity from 
inventory and updates stock levels. 
Stimulus: Stock level falls below reorder point. Response: System generates low stock alert 
notification. 
Stimulus: Medicine approaches expiry date (within 30 days). Response: System generates 
expiry alert notification.

6. Other Requirements 
6.1 Database Requirements 
• The database shall support ACID transactions for data integrity 
• The database schema shall be normalized to at least 3rd Normal Form (3NF) 
• The database shall support foreign key constraints for referential integrity 
• The database shall implement appropriate indexing for query performance 
6.2 Legal and Regulatory Requirements 
• The system shall comply with Pharmacy and Poisons Board of Kenya regulations 
• The system shall maintain prescription records as required by law 
• The system shall comply with data protection regulations for patient information 
6.3 Documentation Requirements 
• User Manual: Comprehensive guide for pharmacy staff 
• Technical Documentation: System architecture and code documentation 
• Training Materials: Quick reference guides and training presentations 
6.4 Portability Requirements 
• The system shall be deployable on standard Windows or Linux servers 
• The system shall be accessible from any modern web browser 
• The system database shall be portable between MySQL and PostgreSQL
